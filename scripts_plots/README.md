# scripts_plots — MuLAN ΔΔG scaling figure

Renders the **performance-and-cost vs PLM scale** figure for the S1102 ΔΔG task, in
the "emergent-property vs parameters" reference style.

## Files

| File | Role |
|---|---|
| `plot_ddg_scaling.py` | the plotting script (data-driven; no code edits to add a model) |
| `ddg_scaling_data.csv` | the data — one row per model/config; edit this to update the figure |
| `ddg_scaling.png` / `.svg` | generated outputs (regenerated by the script) |

## Usage

```bash
# needs matplotlib + pandas. On macOS the repo `.venv` has them
# (pip install matplotlib pandas if missing):
.venv/bin/python scripts_plots/plot_ddg_scaling.py
# -> writes ddg_scaling.png and ddg_scaling.svg next to the script
# (On the Linux box, use any env with matplotlib+pandas, e.g. ~/.venvs/mulan-esmc.)
```

To **add or update a result**: edit `ddg_scaling_data.csv` and re-run — no code changes.
Values come from `RESULTS.md` (master table §5/§5a/§11/§12 + runtime/footprint §7).

## What the figure shows

- **Top panel** — ΔΔG performance (Pearson r on S1102, mutation-based 10-fold CV) vs
  encoder parameters (log x). Marker **shape** encodes the series and marker **color**
  encodes where that CV10 was *trained* (`run_platform`):
  - Dots = sequence-only PLMs (`seq_cv10`); diamonds = the same PLM with Tier-1
    augmentation (`aug_cv10`), drawn as a short vertical connector to its own base
    (the per-model aug lift).
  - **Blue family** (dark navy dot / light blue diamond) = CV10 trained on the **Linux
    40c CPU box**. **Magenta family** (dark magenta dot / light magenta diamond) = CV10
    trained on **Apple M4 Pro (MPS)**. Only `Ankh3-large` and `Ankh3-xl` are currently
    MPS-trained; everything else measured is a Linux run.
  - Grey dashed line = the MuLAN paper target (0.868, `reference` series).
- **Bottom panel** — cost: peak RAM (GB, log y) vs params, each point annotated with its
  embedding-generation runtime **and the platform that produced it** (`Linux 40c` = the
  40-thread CPU box; `M4/MPS` = Apple M4 Pro / 48 GB / MPS). A row measured on both boxes
  (e.g. ProstT5) shows both runtimes on separate lines; a red dashed line marks the CPU
  box's 62 GB RAM ceiling. Note this panel's platform tag (`platform`/`emb_gen_min_mps`)
  is about **embedding-generation** timing, which is independent of the top panel's
  color (which is about where **CV10 training** ran — see `run_platform` below; e.g.
  ProstT5 has an MPS embedding-gen time but its CV10 point is still blue/Linux). A
  footer caption decodes both.
- **Pending** models (blank `pcc`) render as a dotted vertical guide through both panels
  (e.g. AIDO-16B) until their number lands.

## CSV schema

One row per model/config. Columns:

| Column | Meaning |
|---|---|
| `model` | display name |
| `params` | encoder parameter count (e.g. `2.8e9`); the x-axis value |
| `pcc`, `pcc_std` | 10-fold CV Pearson r and cross-fold std. **Blank `pcc` ⇒ pending** (vertical placeholder) |
| `series` | `seq_cv10` (sequence-only) \| `aug_cv10` (+Tier-1 aug) \| `reference` (paper target) \| `pending` |
| `status` | `measured` \| `reference` \| `pending` |
| `label` | `1` = draw the big inline model name (reference-figure style); `0` = legend only |
| `dx`, `dy` | label offset in points on the PCC panel (nudge to avoid overlaps) |
| `peak_ram_gb` | peak RAM for embedding generation (GB); blank = n/a → not plotted in cost panel |
| `emb_gen_min` | embedding-gen wall time (min, 1444 seqs) on the **primary** platform (`platform` col); blank = not logged |
| `lineage` | **model-family tag** — see below |
| `emb_dim` | per-residue embedding vector length; shown under the inline label. Blank = omit |
| `est_ram_gb` | **estimated** peak RAM (GB) for a pending row — annotates its cost-panel placeholder |
| `platform` | where `emb_gen_min`/`peak_ram_gb` were **measured**. Existing CPU runs use `Linux 40c CPU / 62G` (40-thread Linux box, 62 GB ceiling). Blank = not measured on that box |
| `emb_gen_min_mps` | embedding-gen wall time (min, 1444 seqs) measured on **Apple M4 Pro / 48 GB / MPS** — a *second* platform, distinct from `platform`/`emb_gen_min`. Blank = not measured on MPS |
| `run_platform` | where this row's **CV10 itself was trained** — `mps` (Apple M4 Pro / MPS) \| `linux` (Linux 40c box) \| `reference` (paper number) \| `pending` (no run yet). **Independent of `platform`/`emb_gen_min_mps`**, which only time embedding generation (e.g. ProstT5 has an MPS embedding-gen time but its CV10 ran on Linux, so `run_platform=linux`). Drives the top-panel marker color: `mps` → magenta family, `linux` → blue family |

### Same-family scaling lines (`lineage`)

Rows that share a **non-blank `lineage`** tag are auto-connected by a **dotted** line in
the top panel (param-sorted), drawn only when ≥2 measured points share the tag. This is
the reference-figure "within-family scaling" sweep, and it triggers a "Same-family scaling
(shared lineage)" legend entry. The connector is drawn in **neutral grey** (not blue or
magenta) because a family can span both platforms — e.g. the Ankh lineage below mixes a
Linux point (`Ankh-large`) with two MPS points (`Ankh3-large`, `Ankh3-xl`); grey avoids
implying the line "belongs" to one platform's color.

Current use:
- `lineage=ESM` — `ESM2-3B` → `ESM C 6B` (same 2560-d width; the +0.043 PCC gain is newer
  pretraining, not just params — see RESULTS.md §12).
- `lineage=Ankh` — `Ankh-large` → `Ankh3-large` (same 1536-d, newer generation) → `Ankh3-xl`
  (2560-d scale-up). Shows Ankh3 ≈ Ankh-large and only +0.008 for large→xl (RESULTS.md §13).

To add another family sweep, give its rows a shared tag (e.g. `ESM C 300M / 600M / 6B` all
`lineage=ESM_C`). Blank `lineage` = standalone point, no line (e.g. ProstT5).

### Platform color coding (`run_platform`)

The top panel's marker color shows **where CV10 training ran**, independent of shape
(dot=seq, diamond=aug):

| `run_platform` | Color family | Current rows |
|---|---|---|
| `linux` | Blue (dark navy seq / light blue aug) | `ProstT5 (AA)`, `Ankh-large`, `ESM2-3B`, `ESM C 6B`, `ProstT5 +aug`, `Ankh +aug`, `AIDO.Protein-16B` |
| `mps` | Magenta (dark magenta seq / light magenta aug) | `Ankh3-large`, `Ankh3-xl` |
| `reference` | Grey dashed (unaffected) | `MuLAN-Ankh (paper)` |
| `pending` | Grey dotted placeholder (unaffected) | none currently |

To tag a new MPS-trained run (e.g. an upcoming SaProt run on the Mac), set
`run_platform=mps` on its row — no code changes needed. The magenta *aug* shade
(`aug_cv10_mps` in `plot_ddg_scaling.py`) is already wired up even though no MPS `aug_cv10`
row exists yet; its legend entry appears automatically once one does.

## Scope

Only **mainline** PLM runs (the cross-PLM 10-fold CV comparison + Tier-1 aug + paper
reference + pending). Layer-selection / structure-fusion experiments (run3/run6 series)
are intentionally **excluded** — they vary embedding layer/structure, not model scale, so
they don't belong on a params axis.
