# Training hyperparameters — all MuLAN runs (SKEMPI ΔΔG)

> Consolidated entry point for all results: [`../docs/RESULTS.md`](../docs/RESULTS.md). This
> is a deep-dive sub-doc.

Single reference for the hyperparameters behind every MuLAN training run in this
fork. Companion to `../docs/history/PLM_COMPARISON_S1102.md`, `RESULTS_PROSTT5.md`,
`RESULTS_CV10.md`, and `AUGMENTATION.md`. All runs are **from-scratch** training of
a randomly-initialized `LightAttModel` (not the released `mulan-ankh` checkpoint).

## Shared setup (constant across every run unless noted)

**Data**
- Benchmark: SKEMPI **S1102** single-mutation ΔΔG — `S1102_filtered.tsv`, 1100
  mutations across 110 complexes (S1102 minus PDB `2I9B`, SKEMPI-v1-only).
- WT sequences: `wt_sequences.fasta`, extracted from SKEMPI 2.0 cleaned PDBs with
  mutation-consistent numbering.
- Per-residue PLM embeddings cached once and reused (`scratch/embeddings/` Ankh,
  `scratch/embeddings_prostt5/` ProstT5); `nn.LazyConv1d` adapts to embedding width.

**Split** (`mulan.data.split_data`, `random_state=42`)
- run1–run4: one mutation-based 70/15/15 split → **769 train / 157 val / 174 test**.
- S1102 CV runs: `num_folds=10, add_validation_set=True` → per fold **880 / 110 / 110**
  (test = fold *i*, val = fold *i−1*, train = other 8 folds).
- Benchmark CV runs (S1131/S4169/S2003): same `num_folds=10` recipe; per-fold sizes vary
  by dataset (below).

**Model** (`models/config/lightatt_default_config.json`)

| Param | Value |
|---|---|
| `hidden_size` | 64 |
| `last_hidden_size` | 40 |
| `kernel_sizes` | [1, 5, 9] |
| `hidden_dropout_prob` | 0.1 |
| `conv_dropout` | 0.1 |
| `padding_value` | 0 |
| `add_scores` | false |
| input channels | `LazyConv1d`, auto = PLM embed dim (Ankh 1536 / ProstT5 1024 / concat 2048) |

**Optimization** (identical across all runs)

| Param | Value |
|---|---|
| Optimizer | AdamW, `weight_decay=0.01` |
| Learning rate | 5e-4 |
| LR scheduler | `ReduceLROnPlateau(mode="min", factor=0.5, patience=5)` |
| Batch size | 32 |
| Early stopping | `EarlyStoppingCallback(patience=10)` on eval loss |
| Best-model selection | `load_best_model_at_end=True`, `metric_for_best_model="loss"` |
| Eval / save strategy | per epoch |
| Seed | `set_seed(42)` |
| Hardware | CPU-only (40-core box; some early runs slowed ~6× by contention) |

## Per-run hyperparameters (run1–run4, single split)

Only the columns below vary; everything else is the shared setup above. "Max ep" is
the configured `--num_epochs`; training restores the best val-loss checkpoint.

| Run | PLM | Embedding (dim) | Augmentation | Train N | Max ep | Test PCC | RMSE |
|---|---|---|---|---|---|---|---|
| run1 | Ankh | last layer (1536) | none | 769 | 50 | 0.757 | 1.531 |
| run2 | ProstT5 (AA) | last layer (1024) | none | 769 | 50 | 0.740 | 1.584 |
| run3a | ProstT5 (AA) | layer 7 (1024) | none | 769 | 50 | 0.648 | 1.782 |
| run3b | ProstT5 (AA) | concat 7⊕10 (2048) | none | 769 | 25 | 0.429 | 2.193 |
| run4a | Ankh | last layer (1536) | reverse + identity | 1629 | 25 | **0.769** | 1.510 |
| run4b | ProstT5 (AA) | last layer (1024) | reverse + identity | 1629 | 25 | 0.738 | 1.611 |

- **run3b/run4a/run4b used 25 epochs** (not 50) because the host was ~6× slowed by
  contention; overfitting in run1/run2 set in before epoch 25 and the best-val
  checkpoint is restored, so the reduction is near-lossless.
- **Augmented runs (run4a/b)** train on 1629 examples = 769 base + reverse-mutation
  (antisymmetry) + identity (ΔΔG=0) anchors. Generated by `experiments/augment.py`.
  See `AUGMENTATION.md`.
- ProstT5 layer-swapped embeddings (run3a/b) generated by
  `experiments/gen_layer_embeddings.py`. See `LAYER_PROBE.md`.

## Cross-validation runs (10-fold)

Same model + optimization as above; **50 max epochs**, augmentation none, per-fold
880 train / 110 val / 110 test. Driver `scratch/cv10_driver.sh` (4 folds concurrent,
10 CPU threads/job), aggregator `scratch/cv10_aggregate.py`. Full per-fold table in
`RESULTS_CV10.md`.

| Run | PLM | Embedding (dim) | Folds | Max ep | Test PCC (mean ± std) | RMSE |
|---|---|---|---|---|---|---|
| cv10_ankh | Ankh | last layer (1536) | 10 | 50 | **0.832 ± 0.057** | 1.310 |
| cv10_prostt5 | ProstT5 (AA) | last layer (1024) | 10 | 50 | 0.805 ± 0.055 | 1.426 |

Early stopping was active — folds halted at epochs 40–50 (e.g. Ankh folds reached
[47,50,50,50,50,40,50,40,44,50]).

### Benchmark CV runs (S1131 / S4169 / S2003)

**Identical model + optimization to the S1102 cv10** (`lightatt_default_config`, AdamW
wd 0.01, lr 5e-4, batch 32, ReduceLROnPlateau 0.5/patience 5, early-stop 10, 50 max ep,
best-val checkpoint, seed 42, CPU). The only changes are the **dataset** and per-fold sizes.
Each dataset is run for **both PLMs** (Ankh + ProstT5) → 3 datasets × 2 PLMs × 10 folds =
**60 fold-trainings**. Datasets/overlaps documented in `BENCHMARK_DATASETS.md`; ΔΔG follows
GeoPPI's `−RT·ln(Kd_mut/Kd_wt)`; all three restricted to **single-chain-per-partner**
complexes (MuLAN's one-sequence-per-partner design, as for S1102).

| Dataset | Muts / complexes | Per-fold train / val / test | Embedding (Ankh / ProstT5) | Max ep |
|---|---|---|---|---|
| S1131 | 1127 / 110 | 901 / 112 / 114 | last layer (1536 / 1024) | 50 |
| S4169 | 2497 / 211 | 1997 / 249 / 251 | last layer (1536 / 1024) | 50 |
| S2003 | 1124 / 174 | 899 / 112 / 113 | last layer (1536 / 1024) | 50 |

- **Data prep:** `experiments/build_benchmarks.py` (tables + shared `wt_sequences.fasta`,
  structure-validated, 0 WT-residue mismatches). S1131/S4169 from GeoPPI's CSVs, whose
  selections are Xiong et al.'s and mCSM-PPI2's respectively; S2003 derived
  (non-Ala SKEMPI singles, deduped).
- **Embeddings:** union of 3,183 sequences (S4169 is the superset), prewarmed once per PLM by
  `scratch/bench_prewarm.sh` into the shared S1102 caches (`scratch/embeddings`,
  `scratch/embeddings_prostt5`) — 1,445 reused, ~1,738 newly generated per PLM.
- **Driver** `scratch/bench_cv_driver.sh` (4 folds concurrent, 10 CPU threads/job, resumable —
  skips folds with an existing `all_results.json`); **aggregator** `scratch/bench_aggregate.py`
  → `RESULTS_BENCHMARKS.md` (Pearson r + Spearman ρ mean±std per dataset, paired Ankh−ProstT5).
- **Metrics:** `default_compute_metrics` reports `test_pcc` (Pearson r) and `test_scc`
  (Spearman ρ) per fold — both are the benchmark metrics reported throughout.

_Results land in `RESULTS_BENCHMARKS.md` when the CV completes (≈1.5 days, 60 folds)._

## CLI reference

Each run is one `mulan-train` invocation, e.g. run1:

```bash
mulan-train \
  --train_data <split>/S1102_filtered_train.tsv \
  --eval_data  <split>/S1102_filtered_val.tsv \
  --test_data  <split>/S1102_filtered_test.tsv \
  --train_fasta_file wt_sequences.fasta --test_fasta_file wt_sequences.fasta \
  --embeddings_dir scratch/embeddings --plm_model_name ankh \
  --model_name_or_config_path models/config/lightatt_default_config.json \
  --save_model True --num_epochs 50 --batch_size 32 --learning_rate 5e-4 \
  --early_stopping_patience 10 --report_to none
```

Benchmark CV folds use the same flags with dataset-specific paths, e.g. S4169 fold 0 / Ankh:

```bash
mulan-train \
  --train_data scratch/benchmarks/S4169/cv_splits/fold_0/S4169_train.tsv \
  --eval_data  scratch/benchmarks/S4169/cv_splits/fold_0/S4169_val.tsv \
  --test_data  scratch/benchmarks/S4169/cv_splits/fold_0/S4169_test.tsv \
  --train_fasta_file scratch/benchmarks/wt_sequences.fasta \
  --test_fasta_file  scratch/benchmarks/wt_sequences.fasta \
  --embeddings_dir scratch/embeddings --plm_model_name ankh \
  --model_name_or_config_path models/config/lightatt_default_config.json \
  --save_model True --num_epochs 50 --batch_size 32 --learning_rate 5e-4 \
  --early_stopping_patience 10 --report_to none --disable_tqdm True
```

Defaults baked into `mulan/train_utils.py` / `scripts/train.py` (AdamW wd 0.01,
ReduceLROnPlateau 0.5/patience 5, seed 42, best-val checkpoint) are not CLI flags.

## Not training runs

The layer probes (`probe_ankh.md`, `probe_prostt5.md`) are **linear** ridge/logistic
readouts over frozen per-layer PLM features (`experiments/layer_probe.py`), not
MuLAN training, so their hyperparameters are out of scope here. See `LAYER_PROBE.md`.
